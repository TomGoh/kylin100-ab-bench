# 静置及待机自动窗口

`abbench.idle.run_idle(serial, directory, kind, duration_s, mode)` 提供亮屏静置和熄屏窗口。调用者必须指定 1–1800 秒的整数时长；正式窗口、验证窗口和模式顺序由测试套件选择。模式只是调用者标签，不代表框架已经确认镜像身份。每次必须使用新输出目录。

```python
from abbench.idle import run_idle

idle = run_idle("T11206HXH6600007", "runs/idle-001",
                kind="screen_on_idle", duration_s=480, mode="xhyper")
standby = run_idle("T11206HXH6600007", "runs/standby-001",
                   kind="screen_off_standby", duration_s=900, mode="xhyper")
```

模块保存原始屏幕状态和两项实际会调整的设置：`screen_off_timeout` 与 `stay_on_while_plugged_in`。它统一延长屏幕超时并暂时取消插电保持唤醒，使用明确的唤醒键、主页键和休眠键，不使用含义依当前状态变化的电源切换键。它不改变亮度、频率、热管理、充电控制或未知电源节点。调用者应在测试套件外固定相同亮度、刷新率、应用和锁屏条件；发送主页键本身不能证明桌面已解锁。

## 设备状态的核对

本机真实 `dumpsys power` 只有全局 `mWakefulness=Awake`，其中 `Display Power:` 打印对象信息，没有旧格式的 `state=ON/OFF`。模块结合实际 `dumpsys display` 中唯一默认候选显示设备的 `state` 和 `committedState` 核对：全局处于 Awake 且显示设备已经 ON 才认为亮屏；全局处于 Asleep 且显示设备已经 OFF 才认为熄屏。字段缺失、多个候选、状态矛盾或仍在过渡均不能判定成功。显示状态只在窗口边界核对，没有连续监视；自行亮屏等窗口内变化仍是限制。

亮屏窗口复用现有 Perfetto 采集器，启动一个有有限存活时间的私有采集并记录开始、结束事件，最终停止并导出。模块没有同时运行 shell 电池采样器。结果中的 `capture_window_start` 和 `capture_window_end` 保留设备时钟事件，便于套件截取正式静置窗口；原始采集还包含窗口前后的一部分准备时间。有限采集最长 1800 秒，接近该上限的窗口必须额外检查采样覆盖，不能因为采集进程成功就认为完整覆盖了所有端点。

熄屏窗口只在起止边界读取累计电荷、端点电压、启动标识、设备时间和系统休眠统计。窗口中只在控制端分段等待并写控制端日志，没有 ADB 轮询、Perfetto、设备定时采样或主动获取唤醒锁。测试套件应在开始前核对没有其他会干扰休眠的采集或应用；本模块不擅自停止其他会话。

`dumpsys suspend_control_internal` 的成功次数与总休眠时间都必须增加，结果才标记为 `screen_off_standby`。没有可读证据、没有实际休眠或统计值倒退时，结果降级为 `screen_off_idle`，不能把熄屏当成深度待机。缺少该服务不会伪造零值，也不会阻止保存其他窗口数据。

## 端点时间与功耗范围

每个端点在采样前后读取设备 `/proc/uptime` 及启动标识，拒绝跨开机或时间倒退。`elapsed_boottime_s` 使用实际端点起始时间之差，并同时保存端点读取区间推导的保守时长范围，不用预定睡眠时长代替真实经过时间。设备时间被保留为包含系统休眠的启动后时钟来源，控制端单调时间仅用于操作及误差记录，不相互转换。

终点的屏幕核对、主动唤醒和端点读取会影响设备状态。`wake_overhead` 保存第一次终点查询、唤醒请求及端点返回的时间，明确这些开销包含在累计端点窗口内；它不能提供完全没有终点唤醒扰动的待机功耗。

电压与累计电荷仅作为候选微伏、微安时读数保存，默认单位和累计计量未验证。USB 状态保留为 `physical_usb_online`，不会自动填入真实外部输入隔离字段。窗口采集成功时 `valid=true` 只表示控制与证据采集成功；默认 `power.valid=false`，功率和能量为空，其他测试仍可继续。

只有调用者显式交付 `power_config` 并标明 `units_validated=true`、`counter_validated=true` 时，模块才调用已有端点分析器。分析器继续核对累计分辨率、符号、窗口及供电范围；若使用整机电池供电边界，还必须交付真实输入隔离证据和 `external_online_verified`。该字段不来自物理 USB 在线标志。满电短窗累计量不变会被拒绝，不会报告零瓦。亮屏窗口也保留端点法辅助结果，主项仍由套件分析 Perfetto 时间序列。

## 失败与恢复

模块将已尝试修改的设置提前登记，即使写入超时也尝试恢复可能已经生效的值。退出时核对仍处于原来的开机，再反向恢复设置、读回验证并恢复原始亮屏或熄屏状态；原始缺省设置使用删除恢复。跨开机或身份无法确认时，框架不向另一次开机写恢复值，而是在 `restore` 中明确记录尚未恢复的设置。恢复失败会使窗口无效。

运行目录保留逐命令标准输出、错误输出、超时、主机事件日志和 `idle.json`。无效窗口保留已取得端点与原因，未知时长不补零。模块已经检查真正休眠与没有休眠、已知端点能量、未验证累计量、满电恒定累计量、USB 边界误用、设置写入超时、跨开机恢复和原始缺省值恢复。设备实际自动窗口仍需由主会话验证。
