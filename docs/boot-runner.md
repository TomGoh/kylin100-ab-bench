# 启动观察器

`abbench.boot.measure_boot(serial, directory, timeout_s=180, reboot=False)` 是有总截止时间的上层启动观察器。默认只读取设备，先保存旧启动标识，再等待外部执行重启；它不刷写镜像、不切换模式、不调整设备设置。调用者必须在实际重启之前启动观察器。如果运行时设备已经完成新启动，工具只能把它作为旧启动，不能追溯本次重启耗时。

```python
from abbench.boot import measure_boot

result = measure_boot("T11206HXH6600007", "runs/boot-001", timeout_s=180)
# 观察器等待时，由镜像负责方或用户执行已经授权的重启。
```

只有调用者显式设置 `reboot=True` 才会发送一次普通 `adb reboot`。执行方应先向用户说明即将重启以及待测模式。框架不能根据单个属性推断运行模式，模式和镜像身份由该次运行的镜像清单另行约束。

## 有效启动与终点

观察器通过 `su 0` 读取启动标识、`sys.boot_completed` 和 `/proc/uptime`。它在同一探测内分别读取前后两次启动标识，要求两者一致；随后必须观察到不同于旧启动的标识，并在这个新启动中观察到 `sys.boot_completed=1`。旧系统的完成属性、USB 断连、ADB 恢复或 `wait-for-device` 都不构成新启动完成。

探测结束后，工具保存当前开机的 `bootstat -p`、全部属性和事件缓冲区日志，再核对启动标识与完成属性。辅助记录权限不足或命令失败不会自动使启动终点无效，原始错误仍保留。最终标识无法核对、采集期间再次重启或完成属性不稳定时，该次记录为无效。

默认不观察桌面。调用者可以传入 `desktop=True`，工具在系统完成后最多再观察 15 秒，并服从剩余总预算。它动态解析 HOME 活动包名，联合核对用户 0 已解锁、启动动画已停止和当前 `mResumedActivity` 属于该桌面包。它保存原始证据，不调用界面树采集器，也不发送解锁或绘制操作。字段不支持或无法证实条件时，该阶段保留空值及原因，已经证实的系统完成仍可有效。

这些条件只证明“桌面活动已恢复且用户已解锁”，不提供首次绘制证据。成功时 `desktop_resumed_observed.value=true`，`request_to_desktop_resumed_observed_s` 是首次观察该状态的代理上界，`request_to_desktop_resumed_interval_s` 同时保留误差区间。完整桌面绘制就绪仍使用 `desktop_ready.value=null`、`reason=first_draw_not_verified`，不能将这两个终点混为一谈。跨开机桌面证据使整次记录无效。

## 计时边界

所有控制端时间均来自实际运行 ADB 的主机的 `time.monotonic`。每次调用记录发送前与返回后时间，包含传输及命令延迟。设备启动后时间、日志时间和启动统计值保留原始时钟域，不与主机时间直接相减。

`system_complete_interval_host_s` 的上界是第一次成功观察新启动完成的探测返回时间。若此前已经观察到同一新启动尚未完成，下界采用最后一次尚未完成探测的发送时间。这是保守观测区间；命令读取属性的准确时刻位于调用内部，不能以轮询返回点冒充准确完成时刻。无法观察新启动的未完成状态时，外部重启样本的下界为空；显式请求重启的样本则以请求起点作为保守下界。

| 输出 | 边界与限制 |
|---|---|
| `request_to_system_complete_interval_s` | 仅显式请求重启时存在，表示请求到系统完成的暖重启代理区间，包含传输及引导。 |
| `request_to_system_complete_observed_s` | 仅有效的显式重启样本存在，等于上述区间上界。可用于统一比较首次观察完成的代理时长，报告仍须同时给出误差区间。 |
| `new_boot_access_interval_host_s` | 首次可读取新启动标识的调用区间，不代表连接硬件恢复的准确时刻。 |
| `new_boot_access_to_system_complete_interval_s` | 新启动首次可访问到观察系统完成的代理区间。系统可能在 ADB 恢复前已经完成，下界为零只表示保守界限。 |
| `new_boot_access_to_system_complete_observed_s` | 仅有效样本存在，等于首次可访问到系统完成代理区间的上界，不能与重启请求起算的代理时长混合。 |
| `boot_transition_interval_host_s` | 最后读到旧标识至第一次读到新标识的保守区间，不代表按键、外部刷写或外部重启命令的触发时间。 |
| `external_trigger_host_s` | 始终为空，观察器无法知道外部触发时刻。 |
| `elapsed_s` | 始终为空；本工具交付区间，避免把其中一个轮询点当作准确值。 |

这些输出都不能命名为完整冷启动时间。设备内 `bootstat`、属性和事件日志只作为阶段辅助记录，保留混合单位；例如本机 `absolute_boot_time` 与 `boot_complete` 不能通过统一倍率转换。引导程序阶段报告为零不证明真实引导耗时为零。

## 失败与原始记录

每次运行必须使用新目录。工具写出 `observations.jsonl`、逐命令的标准输出与错误输出，以及以临时文件完成后改名的 `boot.json`。失败时保留 `valid=false`、原因、已有启动标识和已观察的区间，未知时长为空，不补成零。

总截止时间默认 180 秒，最多 300 秒，包含旧标识读取、可选重启请求、轮询、辅助记录及最终核对。每条 ADB 命令默认最多 3 秒、允许上限 5 秒，并使用不超过剩余预算的超时；轮询等待也不超过剩余时间。工具优先保留最终身份核对的预算，必要时跳过辅助记录并说明原因。操作系统调度可能使超时返回略晚；截止时间后的输出不能建立有效启动终点。它不会通过无限 `adb wait-for-device` 掩盖设备不可访问。`boot_id` 仅在最终核对有效后填入，可直接用于该次运行；`new_boot_id` 还会保留失败途中观察到的候选标识。

本模块已用模拟的正向启动、旧启动重连、传输失败、单次及再次重启、辅助记录失败、长命令超时和实际预算耗尽输入检查。真实设备的启动计量仍需由执行方完成，模拟检查不等同于现场重启验证。
